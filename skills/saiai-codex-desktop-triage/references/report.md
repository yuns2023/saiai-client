# 可转交报告模板

将下列模板填入 `saiai-desktop-report.md`。不得包含原始日志附件。
每个证据使用 E1、E2 等编号；引用文件只用路径别名。
最终写入前再次检查所有自由文本是否包含凭据、隐私或带 query 的 URL。

```markdown
# SAIAI Desktop 诊断报告

report_schema: 1
skill_revision: <安装来源 commit；未知则 unknown>
采集时间/时区:
诊断模式: 只读
结论: <故障层；confirmed / probable / unresolved>

## 症状与复现
- 用户期望 / 实际行为:
- 故障面: 登录 / Chat / Work-Codex / 历史 / 附件 / 设置 / launcher
- 原始启动入口:
- 已有失败时间和时区:
- 最短操作步骤（不含消息正文）:
- 最近变更；最后可用版本（未知则 unknown）:

## 版本与环境
| 项目 | 值 | 证据 |
|---|---|---|
| OS / 架构 | | |
| SAIAI 版本 / binary SHA-256 | | |
| Desktop 包版本 / 包类型 | | |
| 内置 app-server 版本 | | |
| 系统 CLI 版本（如相关） | | |
| 配置目录/环境关系（路径别名） | | |
| 实际实例与启动时间 | | |
| proxy / CA / SPKI 是否匹配 | | |
| Gateway 版本 | unknown（不要从客户端猜测） | |

## 事件与检查
| 证据 | 时间/时区 | 来源/hop | 安全观察值 | 能证明什么 |
|---|---|---|---|---|
| E1 | | | | |

分别记录：身份控制面、代理选择、TLS、HTTP/WS 握手、首帧、
流完成、资产下载。没检查写 not-tested，不用一个“通过”概括全部。
列出执行过的检查、退出状态、是否有外部网络访问；不保留含 Key 的命令。

## 归因
- 已观察事实（证据编号）:
- 最可能原因 / 置信度:
- 其他可能原因 / 反证:
- 所属组件: CLI / Desktop / Gateway / provider / local-environment / unknown
- 尚缺证据:
- 下一项最小区分检查（注明是否会修改配置或产生真实请求）:

## 给 SAIAI 维护者
- 待验证的不变量与实际差异:
- 建议回归场景（OS、版本、启动入口、配置前态、触发条件、期望行为）:
- 可以用合成凭据/mock 重现的部分:
- 需要客户或管理员补充的证据:
- 是否具备直接修 CLI 的证据: yes / no，理由:
- 建议修复范围（推断，不代表已修复）:
- 修复后验收项: 冷启动登录、复用/重开、原故障面；各项单独标记

## 边界
- 本次新发起模型请求: 0（如非零，写实际数及具体授权；未知不得写 0）
- 外部非模型检查: 数量/类别，或 none
- 变更/重启/凭据读取/原始日志导出: none，或如实说明
- 未验证的平台与功能:
- 脱敏检查: 已移除密钥、Cookie、JWT、邮箱、正文、真实用户路径、
  带 query 的 URL、设备 proof；未知自由文本已省略
```
